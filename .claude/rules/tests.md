# Test rules

- Vitest for unit and integration, Playwright for UI and CLI e2e. Test names state behavior: `it('folds promise reaction jobs into the parent span')`, not `it('works')`.
- Arrange, act, assert; one behavior per test. No loops or conditionals in assertions; `it.each` tables are fine.
- No sleeps. Wait on a condition (event, file exists, port open) with a bounded timeout. Tests are deterministic and independent; use unique temp dirs and clean up.
- Fixtures are generated by running real `zoo/` apps through the collector, committed under `packages/<pkg>/test/fixtures/` with a README and the command that regenerates them. Regeneration is a script, never manual editing.
- Zoo apps each have exactly one planted bottleneck and must produce its finding and only that one. Keep them tiny and dependency-light. They are intentionally naive and not examples of good code.
- Screenshot tests: light and dark, 1440 px wide, one per view, stored in `e2e/__screenshots__/`. Update them intentionally, with a note in the commit.
- Platform-specific behavior (SIGINT on Windows, named pipes) gets explicit `it.runIf(process.platform === ...)` cases.
- Do not mock what you own (engine passes, format). Mock only at true edges (clock, filesystem errors, spawn).
